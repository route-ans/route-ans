    Feature Flags and Minimal Configuration Guide¶

    This document explains how to disable unused features in the ANS Resolution Server.

    Quick Summary¶

    Feature Config Setting Recommendation
    Queue queue.enabled: false ✅ Disable for single instance
    Trust Verification trust.verification.enabled: false ⚠️ Disable for testing only
    Metrics telemetry.metrics.enabled: false ✅ Disable if not monitoring
    Tracing telemetry.tracing.enabled: false ✅ Disable if not using APM
    Cache cache.provider: memory ✅ Use memory for simplicity
    Store store.provider: memory ✅ Use memory for small scale

    Feature-by-Feature Breakdown¶

    1. Queue System¶

    Purpose: Registry event streaming, distributed coordination
    Status: Infrastructure exists but never used
    Impact of disabling: None (it's not being used anyway)

    queue:
  enabled: false      # ← Add this to disable
  provider: memory

    When to enable: - Running multiple resolver instances - Need to process registry webhooks - Want cross-instance cache invalidation

    2. Trust Verification¶

    Purpose: DNS verification, OCSP, certificate validation
    Status: Fully implemented (883 lines of code!)
    Impact of disabling: ⚠️ Not ANS paper compliant - skip DNS checks

    trust:
  verification:
    enabled: false              # ← Disable all verification
    mode: disabled              # disabled | permissive | strict
    requireSignature: false     # Skip JWS signature checks
    requireMerkleProof: false   # Skip CT-style proofs
    checkRevocation: false      # Skip OCSP/CRL checks

    When to enable: - Production deployment - Need ANS paper compliance - Security-critical environment

    What it checks when enabled: - ✅ Registry signature verification - ✅ DNS _ans.<domain> TXT record - ✅ DNS _ra-badge.<domain> TXT record - ✅ TLSA/DANE certificate binding - ✅ OCSP revocation status - ✅ CRL checks

    3. Metrics (Prometheus)¶

    Purpose: Operational metrics, monitoring
    Status: Fully implemented
    Impact of disabling: No /metrics endpoint

    telemetry:
  metrics:
    enabled: false    # ← Disable Prometheus metrics
    port: 9091

    When to enable: - Using Prometheus/Grafana - Need operational visibility - Running in production

    4. Distributed Tracing¶

    Purpose: Request tracing across services
    Status: Implemented but unused
    Impact of disabling: None

    telemetry:
  tracing:
    enabled: false    # ← Already disabled by default
    provider: otlp

    When to enable: - Microservices architecture - Using Jaeger/Zipkin - Need request flow visibility

    5. Cache Provider¶

    Purpose: Speed up repeated lookups
    Status: Always needed
    Options: memory (simple) vs redis (distributed)

    cache:
  provider: memory    # ← Simplest option
  # OR
  provider: redis     # For multiple instances

    Recommendation: - memory: Single instance, development, testing - redis: Production, multiple instances, >1000 req/sec

    6. Store Provider¶

    Purpose: Powers /search and /discover endpoints
    Status: Basic implementation
    Options: memory (simple) vs postgres (full-featured)

    store:
  provider: memory    # ← Simplest option
  # OR
  provider: postgres  # For full-text search (not implemented yet)

    Search limitations with memory store: - Only returns agents that were previously resolved - No full-text indexing - Limited to ~10k agents - Results inconsistent across multiple instances

    7. Rate Limiting¶

    Purpose: Protect against abuse
    Status: Implemented, always recommended
    Can disable but not recommended:

    rateLimit:
  enabled: false      # ⚠️ Not recommended

    Configuration Profiles¶

    Ultra-Minimal (Development Only)¶

    server:
  http:
    port: 8080

cache:
  provider: memory

queue:
  enabled: false

store:
  provider: memory

registries:
  - name: godaddy
    type: godaddy
    enabled: true
    config:
      baseURL: "https://api.godaddy.com/v1"
      apiKey: "${GODADDY_API_KEY}"
      apiSecret: "${GODADDY_API_SECRET}"

trust:
  verification:
    enabled: false

telemetry:
  logging:
    level: info
  metrics:
    enabled: false
  tracing:
    enabled: false

    Use for: Local development, quick testing

    Recommended Minimal (Production)¶

    server:
  http:
    port: 8080

cache:
  provider: memory    # Upgrade to redis for multi-instance

queue:
  enabled: false      # Enable when adding event handling

store:
  provider: memory

registries:
  - name: godaddy
    type: godaddy
    enabled: true
    config:
      baseURL: "https://api.godaddy.com/v1"
      apiKey: "${GODADDY_API_KEY}"
      apiSecret: "${GODADDY_API_SECRET}"

trust:
  verification:
    enabled: true               # ← ENABLE for production!
    mode: permissive            # Start permissive, move to strict
    requireSignature: true
    requireMerkleProof: false   # GoDaddy doesn't support yet
    checkRevocation: true       # Check OCSP/CRL

rateLimit:
  enabled: true

telemetry:
  logging:
    level: info
  metrics:
    enabled: true     # ← Enable for monitoring
  tracing:
    enabled: false    # Optional

    Use for: Single-instance production deployment

    Full-Featured (Scale)¶

    cache:
  provider: redis     # Distributed caching

queue:
  enabled: true       # Enable for event handling
  provider: redis

store:
  provider: postgres  # Full-text search (requires implementation)

trust:
  verification:
    enabled: true
    mode: strict      # Strict enforcement

telemetry:
  metrics:
    enabled: true
  tracing:
    enabled: true

    Use for: Multi-instance, high-scale production

    What Features Are "Dead Weight"?¶

    Based on current usage:

    Feature Lines of Code Actually Used? Safe to Disable?
    Queue ~500 ❌ No ✅ Yes (for now)
    Merkle Proofs ~200 ❌ No ✅ Yes (not supported)
    Event Streaming ~150 ❌ No ✅ Yes (not available)
    Version Listing ~100 ❌ No ✅ Yes (not supported)
    Trust Verification ~883 ⚠️ Disabled ⚠️ Should enable!
    Search/Discovery ~300 🟡 Basic 🟡 Keep for utility
    Metrics ~200 🟡 Optional 🟡 Useful in prod
    Tracing ~150 ❌ No ✅ Yes (unless needed)

    Recommendation¶

    For your use case (single GoDaddy resolver):

    ✅ Keep as-is: - Cache (memory) - Store (memory) - Rate limiting

    ✅ Disable: - Queue (queue.enabled: false) - Tracing (telemetry.tracing.enabled: false) - Metrics if not monitoring (telemetry.metrics.enabled: false)

    ⚠️ Consider enabling: - Trust verification (trust.verification.enabled: true) - for ANS compliance

    The "future-proofing" adds ~1500 lines of code but minimal runtime overhead since features are lazy-loaded and disabled features aren't initialized.
