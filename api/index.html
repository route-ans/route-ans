    API Reference¶

    The Route ANS resolver provides a RESTful HTTP API for resolving agent names.

    Interactive API Documentation¶

    For interactive API exploration, you have two options:

    1. Live Swagger UI (Local Development)¶

    When the resolver server is running locally:

    🚀 Open Swagger UI (Localhost)

    2. Hosted API Documentation (GitHub Pages)¶

    View the API documentation online without running the server:

    📖 View API Docs (GitHub Pages)

    Note: The live Swagger UI connects to your local server and allows testing. The hosted version is for reference only.

    API Endpoints¶

    Resolution¶

    Resolve ANSName¶

    GET /v1/resolve?name={ansName}&version={versionRange}

    Parameters: - name (required): Full ANSName to resolve (e.g., mcp://agent.capability.PID-123.v1.0.0.example.com) - version (optional): Version range for negotiation (e.g., ^1.0.0, ~1.2.3, 1.x, *)

    Response: 200 OK 

    {
  "status": "verified",
  "agent": "mcp://agent.capability.PID-123.v1.2.5.example.com",
  "protocol": "mcp",
  "endpoint": "https://agent.example.com",
  "certFingerprint": "sha256:abc123...",
  "expiresAt": "2026-03-15T10:30:00Z",
  "protocolExtensions": {
    "mcp": {
      "url": "https://agent.example.com/mcp"
    }
  }
}

    Batch Resolve¶

    POST /v1/resolve/batch
Content-Type: application/json

{
  "names": [
    "mcp://agent1.capability.PID-123.v1.0.0.example.com",
    "a2a://agent2.capability.PID-456.v2.0.0.example.com"
  ]
}

    Response: 200 OK 

    {
  "results": [
    { /* resolution record 1 */ },
    { /* resolution record 2 */ }
  ]
}

    Agent Information¶

    Get Agent Details¶

    GET /v1/agent/{ansName}

    Returns detailed information about a specific agent.

    Verify Agent¶

    GET /v1/agent/{ansName}/verify

    Performs explicit verification of an agent's certificate and signatures.

    Health & Monitoring¶

    Health Check¶

    GET /health

    Returns server health status.

    Readiness Check¶

    GET /ready

    Returns whether the server is ready to accept requests.

    Statistics¶

    GET /v1/stats

    Returns resolver statistics (cache hits, verification counts, etc.).

    Metrics¶

    GET /metrics

    Prometheus-format metrics for monitoring.

    Version Negotiation¶

    The resolver supports semantic version ranges for flexible version resolution:

    Format Example Description
    Exact 1.0.0 Exact version match
    Caret ^1.2.3 Compatible (>=1.2.3 <2.0.0)
    Tilde ~1.2.3 Patch updates (>=1.2.3 <1.3.0)
    Greater >=1.0.0 Version or higher
    Less <2.0.0 Below version
    Wildcard 1.x Any minor/patch in major
    Any * Latest version

    Example: 

    # Get latest compatible 1.x version
curl "http://localhost:8080/v1/resolve?name=mcp://agent.PID-123.v1.0.0.example.com&version=^1.0.0"

    See Version Negotiation for detailed documentation.

    Status Codes¶

    Code Meaning
    200 Success - agent resolved and verified
    400 Bad Request - invalid ANSName format
    404 Not Found - agent not registered
    422 Unprocessable Entity - verification failed or incompatible version
    429 Too Many Requests - rate limited
    500 Internal Server Error

    Error Response Format¶

    {
  "error": "error message",
  "code": 404,
  "details": "additional context"
}

    Authentication¶

    The resolver API currently does not require authentication. For production deployments, consider:

    • Using a reverse proxy (nginx, Envoy) for TLS termination and authentication
    • Implementing API key validation
    • Using mutual TLS (mTLS) for agent-to-resolver communication

    Rate Limiting¶

    The resolver includes built-in rate limiting to prevent abuse. Default limits:

    • 100 requests per second per IP
    • 1000 requests per minute per IP

    Rate limit headers are included in responses: 

    X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1642435200

    CORS¶

    Cross-Origin Resource Sharing (CORS) is enabled by default for all origins. Configure via server settings if needed.

    Examples¶

    Using curl¶

    # Simple resolution
curl "http://localhost:8080/v1/resolve?name=mcp://agent.PID-123.v1.0.0.example.com"

# With version negotiation
curl "http://localhost:8080/v1/resolve?name=mcp://agent.PID-123.v1.0.0.example.com&version=^1.0.0"

# Batch resolution
curl -X POST http://localhost:8080/v1/resolve/batch \
  -H "Content-Type: application/json" \
  -d '{
    "names": [
      "mcp://agent1.PID-123.v1.0.0.example.com",
      "a2a://agent2.PID-456.v2.0.0.example.com"
    ]
  }'

    Using JavaScript¶

    // Simple resolution
const response = await fetch(
  'http://localhost:8080/v1/resolve?name=mcp://agent.PID-123.v1.0.0.example.com&version=^1.0.0'
);
const result = await response.json();
console.log(result.endpoint);

// Batch resolution
const batchResponse = await fetch('http://localhost:8080/v1/resolve/batch', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    names: [
      'mcp://agent1.PID-123.v1.0.0.example.com',
      'a2a://agent2.PID-456.v2.0.0.example.com'
    ]
  })
});
const batchResult = await batchResponse.json();

    Using Python¶

    import requests

# Simple resolution
response = requests.get(
    'http://localhost:8080/v1/resolve',
    params={
        'name': 'mcp://agent.PID-123.v1.0.0.example.com',
        'version': '^1.0.0'
    }
)
result = response.json()
print(result['endpoint'])

# Batch resolution
batch_response = requests.post(
    'http://localhost:8080/v1/resolve/batch',
    json={
        'names': [
            'mcp://agent1.PID-123.v1.0.0.example.com',
            'a2a://agent2.PID-456.v2.0.0.example.com'
        ]
    }
)
batch_result = batch_response.json()
